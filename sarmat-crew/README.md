# Sarmat Crew

Нативний Android-застосунок екіпажу для роботи з власними батареями та ручного запису вимірювань.

## Поточні можливості

- вхід обліковим записом екіпажу;
- завантаження списку батарей екіпажу з Monitor API;
- ручне введення напруги кожної комірки та запис вимірювання;
- перегляд повної історії батареї з деталями по комірках.

Адміністраторські функції залишаються у вебзастосунку Monitor.

## Робота без інтернету та синхронізація

Після першого входу та успішної синхронізації застосунок зберігає список батарей, історію й пороги оцінки комірок у локальній SQLite-базі. Перегляд, перевірка напруги, нові вимірювання, чернетки та зміна статусу «У дроні» працюють без мережі. Вимірювання спочатку записується на телефон; закриття застосунку та перезавантаження не видаляють чергу.

- Для ручної синхронізації прокрутіть список до початку, довго потягніть вниз та відпустіть після підказки. Горизонтальний свайп батареї залишається дією «У дроні / Зняти».
- У хедері показано час від останньої повністю успішної синхронізації та кількість ненадісланих змін. Натисніть цей напис для подробиць або доступного без жесту запуску синхронізації. Кнопку «Оновити» з меню прибрано.
- WorkManager надсилає зміни за наявності мережі, повторює тимчасові помилки із затримкою та запускає періодичну перевірку. Android може відкладати фонову роботу через енергозбереження; ручний свайп запускає перевірку одразу.
- Сервер зберігає початковий час вимірювання. Кожна операція має постійний UUID; її виконання та підтвердження записуються в одній транзакції, тому повтор після втраченої відповіді не створює дублів.
- Статус «У дроні» надсилається як бажане значення з очікуваним попереднім станом. Конфлікти з іншим пристроєм показуються в хедері. Через «Розібрати зміни» можна прийняти актуальний серверний статус, після чого за потреби позначити батарею знову. Конфлікт статусу не блокує незалежні вимірювання.
- Відхилені сервером вимірювання залишаються на телефоні. У подробицях синхронізації можна виправити їх або явно видалити локальну копію. Уже підтверджені сервером вимірювання редагуються адміністратором у вебзастосунку.
- Після завершення сесії локальна робота залишається доступною; для надсилання потрібен повторний вхід. Дані розділені за сервером, користувачем та екіпажем. Вихід не видаляє чергу, але інший обліковий запис її не бачить і не надсилає.

### Оновлення бекенду

Перед використанням офлайн-версії встановіть новий бекенд і застосуйте міграцію `0007_offline_sync` стандартною командою `npm run db:migrate` з папки `monitor`. Вона додає таблицю підтверджень `sync_operations`. Застосунок перевіряє підтримку нового API перед надсиланням. На старому бекенді він зберігає чергу й показує, що потрібне оновлення; небезпечного повтору старого `toggle-active` немає.

Модульні тести, включно з SQLite, повторними запитами та жестом, можна виконати без збирання APK: `gradlew.bat :app:testDebugUnitTest`.

## Підключення до Monitor

На екрані входу потрібно вказати адресу backend, наприклад `https://api.example.com`. Для локального тесту телефон і комп’ютер мають бути в одній мережі; використовуйте LAN-адресу комп’ютера, наприклад `http://192.168.1.20:3000`, а не `localhost`.

Для входу використовується обліковий запис із роллю `CREW`. Адміністраторські облікові записи застосунок не приймає. Сесія і адреса сервера зберігаються локально на пристрої.

## Збірка

Відкрийте каталог `sarmat-crew` в Android Studio або виконайте:

```bash
./gradlew assembleDebug
```

Для запуску потрібен Android-пристрій з Android 8.0/API 26 або новішим.

## Автоматична збірка на GitHub

Workflow **Android APK** (`.github/workflows/android.yml`) збирає debug APK:

- після push або pull request зі змінами в `sarmat-crew` чи самому workflow;
- після push тегів `v*`;
- вручну через **Actions → Android APK → Run workflow**.

Використовуються Java 17, Android SDK 36 і Gradle Wrapper проєкту. Workflow виконує лише `:app:assembleDebug`, без запуску тестів.

Після успішного запуску відкрийте **Artifacts → SarmatCrew-debug-…**, завантажте ZIP і дістаньте `app-debug.apk`. Артефакт зберігається 30 днів. Публікація в Google Play або GitHub Releases не виконується.

Це debug-збірка з автоматично створеним ключем підпису runner-а. Ключ може відрізнятися між запусками та від локальної збірки, тому оновлення поверх установленого APK не гарантується. Для регулярних оновлень зі збереженням даних потрібен постійний ключ підпису, налаштований через GitHub Secrets; ключі не слід додавати до репозиторію.

## Збірка та встановлення на телефон

### Windows

1. Встановіть Android Studio. У **SDK Manager** встановіть **Android SDK Platform 36** і **Android SDK Platform-Tools**. Перед першою збіркою відкрийте папку `sarmat-crew` в Android Studio, дочекайтеся синхронізації та встановіть запропоновані компоненти SDK.
2. Увімкніть на телефоні **USB debugging**, під’єднайте його кабелем із підтримкою передачі даних і підтвердьте дозвіл на телефоні.
3. Двічі натисніть **build-and-install.bat** у папці `sarmat-crew`.

Лаунчер перевірить телефон, збере APK, встановить або оновить застосунок і запустить його. Вікно залишиться відкритим, щоб можна було прочитати результат або помилку. Для першої збірки потрібен інтернет для завантаження залежностей.

SDK шукається через `ANDROID_HOME`, `ANDROID_SDK_ROOT` та стандартну папку `%LOCALAPPDATA%\Android\Sdk`; також підтримується `adb.exe` у `PATH`. Лаунчер вибирає JDK 17 або 21: спочатку локальний `.tools\jdk-17`, потім `JAVA_HOME`, `PATH`, стандартні папки Android Studio та встановлених JDK. Java 25, яку можуть містити нові версії Android Studio, для цієї збірки не підходить. Для нестандартного розташування задайте `ANDROID_HOME` та `JAVA_HOME` (JDK 17 або 21). Вибір Java діє лише для процесу лаунчера.

Якщо під’єднано кілька пристроїв, запустіть у PowerShell із папки `sarmat-crew`:

```powershell
.\build-and-install.bat DEVICE_SERIAL
```

Для запуску без паузи наприкінці, наприклад з автоматизації:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-and-install.ps1
```

### Linux / macOS

Увімкніть на телефоні USB debugging, під’єднайте його кабелем і підтвердьте доступ. Потім виконайте з каталогу `sarmat-crew`:

```bash
./build-and-install.sh
```

Скрипт збере debug APK, встановить або оновить Sarmat Crew і одразу запустить його. Якщо під’єднано кілька пристроїв, передайте потрібний serial:

```bash
./build-and-install.sh DEVICE_SERIAL
```

Список serial можна отримати командою `adb devices -l`.
