# SOC батареї

Розрахунок реалізовано в `@sbm/shared` (`battery-soc.ts`). Backend відтворює
історію за часом вимірювання й повертає `currentCharge`. Web та Android
показують цей результат і його джерело.

## Початкова оцінка та розряд

- Замір чекером задає нову початкову оцінку через `voltageToPercent`.
  Збереження комірок не змінено; струм такого виміру — 0 A.
- Для стандартної 12S батареї 36 V відповідає 0%, 50.4 V — 100%.
  Використовуються поточні межі її типу.
- Плагін інтегрує струм з послідовних свіжих SYS_STATUS пакетів:
  `ΔmAh = (Iпопередній + Iпоточний) / 2 × Δсекунд / 3.6`.
  Напруга та струм беруться з одного пакета. Враховується і відомий струм
  споживання підключеного дрона на землі.
- Накопичені mAh від початку сесії передаються при підключенні, дізармі
  та кожні 15 секунд під час ARMED. Контрольні записи не засмічують
  користувацьку історію; вони зберігаються для розрахунку SOC.
- `SOC = початкова оцінка − витрачені mAh / (ємність Ah × 1000) × 100`.
  Розрахунок зберігає дробову точність; результат округлюється й обмежується
  0–100% лише для відповіді.

Нова сесія починає свій лічильник з нуля, але продовжує залишок батареї.
Повторна доставка одного ID і повторення накопиченого значення не списують
ємність двічі. Запізнілі записи обробляються за часом вимірювання.
Нова перевірка чекером уточнює початкову оцінку; повністю заряджений пакет,
підтверджений таким виміром, отримує 100%. Саме підвищення напруги з дрона
після відпочинку або перепідключення не підвищує SOC.

## Калібрування

У типі батареї задається номінальна ємність та необов’язковий
`internalResistanceMilliOhms` — опір **усього пакета**, у мΩ.
У конкретній батареї можна задати `actualCapacityAh` та
`internalResistanceMilliOhmsOverride`. Порожні значення успадковують
налаштування типу; 0 мΩ явно вимикає компенсацію для цієї батареї.
Зміна калібрування перераховує оцінку з первинних даних.

## Неповні дані

Відсутній/некоректний струм або інтервал між пакетами понад 5 секунд
позначає інтеграцію сесії як неповну: невідому витрату не вигадуємо.
При неповній телеметрії з накопиченими mAh SOC зменшується лише на відому
витрату; просідання напруги не списує додаткову ємність.
Без лічильника оцінка за напругою може знизити SOC лише без навантаження.
ARMED або струм понад `max(2 A, ємність Ah × 0.05)` вказують на навантаження.
Поріг струму — наближений захист для старих плагінів без ARMED, не модель опору.
Без початкової оцінки та опору вимір під навантаженням не задає SOC.
Вища напруга не відновлює заряд.
За наявності опору застосовується `Vкомп = V + I × RмΩ / 1000`.
Після прогалин оцінка залишається неповною до нового заміру чекером.
Для батареї без попереднього заміру початкова оцінка береться з першої
телеметричної напруги й позначається як неповна.

`currentCharge.method`: `consumption`, `voltage_compensated` або `voltage`.
`incomplete` повідомляє про неповний облік витрати.
`consumedMahSinceCheck` містить відому витрату після останньої початкової оцінки.
Аварійне завершення плагіна до збереження наступного контрольного запису
може втратити останній незбережений інтервал. Старі записи без струму/mAh
залишаються приблизною оцінкою за напругою.

## Розгортання

1. Застосувати міграції `0015` (струм), `0016` (витрата та калібрування),
   `0017` (стан ARMED).
2. Розгорнути backend та web.
3. Оновити Mission Planner плагін для передавання накопиченої витрати.
4. Оновити Android застосунок для показу джерела SOC і неповноти даних.

Точність залежить від калібрування датчика струму, виміряної ємності
та початкової оцінки. Компенсація опором не усуває всі ефекти відпочинку батареї.
